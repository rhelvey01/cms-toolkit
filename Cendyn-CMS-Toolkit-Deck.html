01 · Overview
What it is

Four skills, one pipeline.

Discover, extract, build and log migrations in any Cendyn CMS module: rooms, offers, venues, events, blog, galleries and sections.

01

Discovery

Maps one template page into a reusable page-type profile.

Read-only
02

Extracts source copy into content.json, every field tagged verbatim, derived or authored.

No CMS access

Creates pages from a profile and content.json. Also places and updates photo galleries.

Writes to the CMS

03 · The skills · Discovery
cendyn-discovery · read-only

Learn a page type once, reuse it every time.

Turns one finished template page in any Cendyn CMS module into a page-type profile: everything the builder needs to create more pages like it. It writes nothing to the CMS.

03 · The skills · Copy
cendyn-copy · no CMS access

Every word knows where it came from.

TagMeaningReview
verbatimCopied character for character from the sourceNo
derivedComputed from source facts, no new wording ("3 Beds" from "3 bedrooms")Spot-check
authoredClaude wrote the wording from source factsAlways
missingThe source can't support the field, so it stays emptyYes
The core ruleNever invent facts. Every verbatim field is checked against the raw source text and downgraded if it doesn't match.
Extraction, most faithful first

03 · The skills · Page builder
cendyn-page-builder · writes to the CMS

Create, fill, save, then verify.

Step 1

Create

Set page-level fields from content, post, then re-read the list to get the new id.

Step 2

Import sections

Paste the section JSON into the Import dialog and confirm the section count.

Step 3

Fill and save

Fill copy and images on the live page, then post. Every field logs applied or missed.

Step 4

Verify

Re-read the edit page, check the public URL returns 200, screenshot the first page.

Don't navigate awayImported sections live only in the page until you save. Leaving the page discards them.
GalleriesBody widget by default, or a gallery section when the site calls for it. Never both on one page.
Safe by defaultPages are built unpublished, writes run one at a time and live checks are cache-busted.
03 · The skills · Migration log
migration-log · no CMS access

One living record per site.

After every job that touches the CMS, before reporting done, the skill appends rows to content-jobs/<site>/migration-log.csv. Read-only discovery gets rows too, so the next session knows what was mapped.

Ten columns
datepromptjobcppropertybackend_urllive_urlsections_updatedresultproblems

One row per page

A job that changes 27 pages adds 27 rows.

Confirmed only

Result records what a re-read confirmed. Anything unchecked is "not verified."

Problems required

Failures, skips and anything that needs a person, on the rows it affects.

No guessing

Unknown dates read "Date not recorded." Saved as UTF-8 with BOM for Excel.

04 · Guardrails
How it's organized

Defaults here, differences outside.

The plugin · safe to share

What's the same on every Cendyn site

  • The four skills, with their schemas and browser helpers
  • Base Cendyn profile: modules, 20 widgets, settings, rooms and venues fields
  • A blank page-type profile and a blank site folder
  • Anonymised worked examples
  • .gitignore blocks logs, CSVs and auth.json
content-jobs/<site> · stays local

What's different about one site

  • instructions.md: special rules and the never-touch list
  • mapping.json: differences, source mapping, section library
  • page-types/: one profile per page type
  • migration-log.csv: the one running log
  • source-files/: exports and files the client handed over

04 · Guardrails
Built to protect client sites

Safe writes, honest reporting.

01

One skill writes

Discovery is read-only. Copy and logging never touch the CMS.

02

Dry run first

The profile is checked against the live form before anything is saved.

03

No invented facts

Authored and missing fields go on a review list before content reaches a client site.

04

Stop on a miss

Any field that doesn't match the profile stops the build and triggers rediscovery.

05

Never borrow a form

Data built from another page's form can overwrite that page, so it's never posted.

06

Client data stays local

Real site work lives in content-jobs/, never in the plugin or the repo.
